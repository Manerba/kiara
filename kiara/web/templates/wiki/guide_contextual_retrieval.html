Contextual Retrieval

Contextual Retrieval reichert Chunks waehrend der Ingestion mit LLM-generiertem Kontext an. Pro Chunk wird ein 2-3-Satz-Prefix generiert, der den Chunk in den Dokumentkontext einordnet. Dadurch verbessern sich sowohl Vektor-Embeddings als auch BM25-Suche.

Ueberblick

Funktionsprinzip

Beim Chunking gehen Dokumentzusammenhaenge verloren. Ein Chunk wie „Die Lieferung erfolgt in 6 Wochen“ ist ohne Kontext (welcher Auftrag? welcher Kunde?) kaum sinnvoll retrievebar.

Contextual Retrieval loest dieses Problem: Vor dem Embedding wird jedem Chunk ein LLM-generierter Kontext-Prefix vorangestellt, der den Chunk im Gesamtdokument verortet. Das Ergebnis sieht so aus: 

Dieser Abschnitt stammt aus einer Auftragsbestaetigung fuer
Kunde Mustermann AG (Auftrag A-2024-0815) und beschreibt
den voraussichtlichen Lieferzeitplan.

Die Lieferung erfolgt in 6 Wochen. Der Kunde wurde
per E-Mail informiert. Die Teillieferung ...

Der Prefix (erste 3 Zeilen) wird vom LLM generiert. Der Rest ist der Original-Chunk. Sowohl das Vektor-Embedding als auch der BM25-Index enthalten den Kontext — Suchanfragen wie „Lieferzeit Mustermann“ finden diesen Chunk nun zuverlaessig.

Position in der Pipeline

Der Enrichment-Schritt ist zwischen Chunking und Embedding eingebettet:

SchrittBeschreibung
1. LadenDatei laden (Docling/DDU, VLM, Standard-Loader)
2. ChunkingText in Chunks aufteilen (RecursiveCharacterTextSplitter)
3. DedupUnveraenderte Chunks ueberspringen (Hash-Vergleich)
4. EnrichmentLLM-Kontext-Prefix pro Chunk generieren
5. EmbeddingChunks in Vektoren umwandeln und in Qdrant speichern

Konfiguration

Globaler Schalter

Contextual Retrieval wird ueber zwei Bedingungen gesteuert — beide muessen erfuellt sein:

  1. Globaler Kill-Switch in /etc/kiara/kiara.yaml oder Admin-UI → KI → Indexierung
  2. Per-Datasource-Flag in den Datenquellen-Einstellungen
# /etc/kiara/kiara.yaml
enrichment:
  enabled: true               # Globaler Schalter (default: false)
  max_context_chars: 6000      # Max. Dokumentkontext fuer den Prompt
  max_workers: 2               # Parallele LLM-Aufrufe
Hinweis: Ohne enrichment.enabled: true in der Config wird kein Enrichment durchgefuehrt — unabhaengig von den Datenquellen-Einstellungen. Aenderungen am globalen Schalter erzeugen erst bei zukuenftigen Indexierungen oder Re-Index-Laeufen neue angereicherte Chunks.

Datenquellen-Einstellungen

Im Tab Datenquellen → Datenquelle bearbeiten → Erweiterte Einstellungen finden sich drei Felder:

FeldBeschreibung
Contextual Retrieval aktivieren Checkbox — aktiviert Enrichment fuer diese Datenquelle
Prompt-Template Dropdown — welcher Enrichment-Prompt verwendet wird. (Standard) nutzt das System-Template enrichment_default.
Enrichment-Backend Dropdown — welches LLM-Backend den Kontext generiert. Pflichtfeld wenn Enrichment aktiv ist. Zur Auswahl stehen alle konfigurierten Backends der Kategorie llm oder cloud.
Wichtig: Ein Enrichment-Backend muss explizit gewaehlt werden. Es gibt keinen stillen Fallback auf ein Standard-Backend. Wird kein Backend gewaehlt, erscheint eine Fehlermeldung beim Speichern.

Backend-Auswahl

Jedes konfigurierte LLM- oder Cloud-Backend kann fuer Enrichment genutzt werden:

Backend-TypVorteileNachteile
Ollama (lokal) Kostenlos, datenschutzkonform, keine Latenz Qualitaet abhaengig vom Modell, VRAM-Bedarf
Anthropic (Claude) Hohe Qualitaet, grosse Kontextfenster Kosten pro Token, Daten werden an API gesendet
OpenAI (GPT) Hohe Qualitaet, schnell Kosten pro Token, Daten werden an API gesendet

Bei Cloud-Backends wird automatisch die Anonymisierung aktiviert (sofern das Backend nicht als trusted markiert ist), um personenbezogene Daten zu schuetzen.

Enrichment-Prompts

Standard-Prompt

KIara liefert einen vorinstallierten Enrichment-Prompt (enrichment_default) mit, der fuer die meisten Anwendungsfaelle geeignet ist. Dieser System-Prompt kann editiert, aber nicht geloescht werden.

Eigene Prompts erstellen

Im Tab KI → Chat (Prompt-Templates) koennen neue Enrichment-Templates angelegt werden:

  1. Neues Template erstellen
  2. chain_type auf enrichment setzen
  3. Prompt-Text mit Platzhaltern verfassen
  4. Speichern

Das neue Template steht anschliessend im Dropdown der Datenquellen-Einstellungen zur Verfuegung. So koennen verschiedene Prompts fuer verschiedene Datenquellen verwendet werden — z.B. ein technischer Prompt fuer CAD-Dokumente und ein allgemeiner fuer E-Mails.

Platzhalter-Referenz

Enrichment-Templates verwenden Platzhalter, die zur Laufzeit durch die tatsaechlichen Werte ersetzt werden:

PlatzhalterBeschreibungPflicht
{document_context} Zusammengesetzter Dokumentkontext (Header + Nachbar-Chunks) Nein
{chunk_text} Der aktuelle Chunk-Text Ja
{file_type} Dateityp (z.B. .pdf, .docx) Nein
{source} Dateipfad Nein
{datasource_name} Name der Datenquelle Nein
Validierung: Der Platzhalter {chunk_text} muss im Template enthalten sein. Fehlt er, wird beim Speichern eine Fehlermeldung angezeigt.

Prompt testen

Bevor ein Prompt produktiv eingesetzt wird, kann er im Tab KI → Chat (Prompt-Templates) getestet werden:

  1. Enrichment-Template oeffnen
  2. Im Bereich Prompt testen ein Backend waehlen
  3. Einen Beispieltext eingeben
  4. Test ausfuehren klicken

Das Ergebnis zeigt den generierten Kontext-Prefix, den vollstaendig gerenderten Prompt und die Verarbeitungsdauer.

Prompt-Versionierung

Versionshistorie

Jede Aenderung an einem Enrichment-Template wird automatisch versioniert. Die aeltere Version wird in der Prompt-History gespeichert (Tabelle prompt_template_history), inklusive:

  • Alter Prompt-Content
  • SHA256-Hash des Contents
  • Zeitstempel der Aenderung

Die Historie ist ueber KI → Chat (Prompt-Templates) → Template oeffnen → Versionen einsehbar.

Rollback

Eine fruehere Version kann jederzeit wiederhergestellt werden:

  1. Template oeffnen → Versionen
  2. Gewuenschte Version waehlen → Wiederherstellen
  3. Bestaetigung

Beim Rollback wird die aktuelle Version ebenfalls archiviert — es geht keine Version verloren. Nach einem Rollback stimmen die bestehenden Chunks nicht mehr mit dem wiederhergestellten Prompt ueberein. Ein Reindex der betroffenen Datenquellen ist empfohlen.

Integritaetspruefung

Im Tab System → Integritaet gibt es eine eigene Pruefung fuer die Enrichment-Prompt-Konsistenz:

Was wird geprueft? Fuer jede Datenquelle mit aktivem Contextual Retrieval werden die Qdrant-Chunks mit dem aktuellen Prompt-Hash verglichen. Jeder enrichte Chunk speichert den SHA256-Hash des Prompts, mit dem er erzeugt wurde (enrichment_prompt_hash im Qdrant-Payload).

StatusBedeutungAktion
OK Alle Chunks wurden mit dem aktuellen Prompt enriched Keine
Warnung Einige Chunks wurden mit einem aelteren Prompt enriched Reindex der betroffenen Datenquelle oder Prompt-Rollback

Die Pruefung zeigt pro Datenquelle eine Aufschluesselung: wie viele Chunks mit welchem Prompt-Hash (und welcher Version) enriched wurden. So laesst sich nachvollziehen, ob eine Prompt-Aenderung bereits durch einen Reindex propagiert wurde.

Performance

Parallelisierung

Bei mehr als 3 Chunks pro Datei werden die LLM-Aufrufe parallelisiert (ThreadPoolExecutor). Die Anzahl paralleler Aufrufe wird ueber enrichment.max_workers in der Config gesteuert (Default: 2).

Einschraenkung: Parallelisierung ist nur bei lokalen (Ollama) Backends aktiv. Cloud-Backends mit Anonymisierung werden sequenziell verarbeitet, um Thread-Safety zu gewaehrleisten.

Skip-Logik

Chunks unter 50 Zeichen (z.B. Ueberschriften, Code-Einzeiler) werden automatisch uebersprungen — der Kontext waere laenger als der Chunk. Diese Chunks behalten ihren Original-Text.

Statistiken

Nach Abschluss der Ingestion werden Enrichment-Statistiken im Log und in den Job-Details angezeigt:

FeldBeschreibung
enrichment_chunksErfolgreich angereicherte Chunks
enrichment_skippedUebersprungene Chunks (zu kurz)
enrichment_errorsFehlgeschlagene LLM-Aufrufe
enrichment_time_msGesamtdauer des Enrichments in Millisekunden
